# 웹켓몬스터 기획 판단 및 작업 인계

작성일: 2026-09-20

## 문서의 목적과 현재 작업 범위

사용자가 제공한 여러 시점의 기획을 바탕으로 현재 판단을 기록한다. 다음 작업자는 이 문서와 실제 코드를 함께 확인한다. 이 문서는 실행 검증 결과나 모든 기획의 최종 확정본이 아니다.

사용자는 기획을 전달한 뒤 “일단 행동하지 말고 프로젝트에 대한 판단만” 요청했고, 이후 그 판단을 문서화하도록 요청했다. 이 세션에서는 일부 코드를 읽었으며, 기능 수정·빌드·테스트·브라우저 실행은 하지 않았다. 문서 작성 요청을 기능 구현 승인으로 해석하지 않는다. 다음 기능 작업은 사용자의 후속 요청 범위에 맞춰 진행한다.

## 프로젝트에 대한 판단

핵심 흐름은 웹 탐색 → 몬스터 발견·포획 → 먹이와 퀘스트로 성장 → 진화 → 행동과 이펙트 획득이다. 사이트의 특징을 몬스터 외형과 행동으로 표현하는 것이 프로젝트의 개성이다.

핵심 기획과 구현 기반은 있으나, 서로 다른 시점의 규칙이 코드와 설명에 함께 남아 있다. 현재 우선순위는 기능 확장보다 프레임, 퀘스트, 먹이, 진화·레벨업의 안정화로 판단한다. 실제 정상 동작 여부는 아직 판정하지 않았다.

## 최신 기획으로 이해한 기준

명시적인 수정사항을 이전 설명보다 우선한다. 아래는 사용자 설명에 대한 현재 해석이며, 코드 구현 완료를 뜻하지 않는다.

| 항목 | 기준 |
| --- | --- |
| 출현·포획 | 페이지 이동·새로고침 시 확률적으로 출현, 한 번에 한 몬스터, 클릭으로 포획 |
| 중복 포획 | 기존 몬스터의 경험치 증가 |
| 구성 | 8계열 × 3단계 외형, 번호 1~24 |
| 성장 | 레벨 1~5, 레벨 3·5에 진화 가능 |
| 진화 | 요구 레벨 충족 및 진화의 돌 필요 |
| 행동 해금 | 레벨 3 액션1, 레벨 4 액션2. 이전의 레벨 2 행동 추가 설명은 대체된 것으로 해석 |
| 상태 | idle, walking, happy, hungry, action1, action2, effect |
| 애니메이션 | 기획상 각 상태 4프레임 |
| 배고픔 | 30분마다 배고픔 상태 |
| 먹이 | 배고플 때 클릭하면 먹이 제공, 경험치 +2, 행복 애니메이션 3회 |
| 액션1 자동 트리거 | 해당 사이트에서 10분마다 |
| 액션2 자동 트리거 | 먹이 3회마다 |
| 수동 행동 | 사용자가 해금한 행동을 클릭하여 실행 가능 |
| 아이템 | 진화의 돌, 경험치 물약 두 종류. 별도 인벤토리 구현 불필요 |

“별도 인벤토리 구현 불필요”는 아이템 수량 저장까지 없앤다는 의미로 단정하지 않는다. 경험치 요구량과 중복 포획 경험치 수치는 기획에서 확정하지 않았다.

### 퀘스트 기획

| 조건 | 기획에 적힌 보상 |
| --- | --- |
| 먹이 10회, 100회 | “경험치 100물약, 진화의돌 2” — 각 조건과 보상의 대응 및 물약 개수는 추가 확인 필요 |

## 코드에서 확인한 차이

아래는 일부 서버 코드를 정적으로 읽어 확인한 내용이다. 프런트엔드 보완 처리, 실제 DB 데이터, 배포 서버 상태는 확인하지 않았다.

| 위치 | 관찰 | 기획과의 관계 |
| --- | --- | --- |
| `backend/src/main/java/webket_monster/backend/usermonster/service/UserMonsterService.java` | 신규 포획 및 먹이 처리에서 다음 배고픔을 `plusHours(3)`으로 설정 | 30분 기준과 다름 |
| 같은 파일의 `feedMonster` | 먹이 처리 자체에서 배고픔 여부 검사 없이 경험치 +2와 시간 갱신 | 서버에서 반복 먹이를 허용할 가능성. API 전체 경로 검증 필요 |
| `backend/src/main/java/webket_monster/backend/usermonster/domain/UserMonster.java` | `addExp` 반복문에 레벨 5 상한 없음 | 최대 레벨 기획과 다름 |
| `backend/src/main/java/webket_monster/backend/quest/service/QuestService.java` | AI 사이트 퀘스트에서 Google 방문으로 Gemini 조건 충족 가능 | Gemini 방문 조건과 다름 |
| 같은 파일 | Gemini·YouTube·Google 각 10회 퀘스트에서 Google 횟수에 Gemini 방문을 합산 | 각각 10회 조건과 다름 |
| 같은 파일 | 활성 몬스터 홈 사이트 10회 방문 시 이펙트 대기 상태 설정 및 액션1 플래그 반환 | 10분마다 액션1이라는 최신 기획과 다름 |

추가 관찰: 서버 진화 서비스는 첫 진화에 돌 1개, 최종 진화에 2개를 요구한다. 이는 현재 구현이며, 사용자가 확정한 소비량으로 단정하지 않는다. 경험치 물약은 서버에서 경험치 100을 추가한다.

## 아직 결정하거나 확인해야 할 사항

- 일일·주간 퀘스트와 누적 업적의 구분 및 초기화 기준. 이전 설명에는 첫 배포 이후 구현 예정이라는 문구도 있으나, 현재는 퀘스트 점검이 우선순위에 포함돼 있다.
- 단계별 진화의 돌 소비량.
- “모든 몬스터 획득”이 8계열 수집인지 24개 외형 수집인지. 현재 서버 계산은 8계열 보유 기준이다.
- 먹이 10회·100회 보상의 정확한 대응과 수량.
- 해당 사이트 10분의 누적·연속 체류 기준, 탭 전환·새로고침·브라우저 종료 시 타이머 처리.
- 먹이 3회 트리거의 집계 범위와 행동 해금 전 횟수 처리.
- 최종 진화 이펙트의 획득·실행 조건과 이후 “이펙트 뽑기”의 관계.
- Google 로그인은 기획상 미확정.

## 후속 점검 순서

사용자가 점검 또는 수정을 요청하면 다음 네 가지를 중심으로 진행한다.

1. **프레임:** 실제 에셋과 매핑, 24개 번호 및 진화 외형, 7개 상태의 프레임 순서·표시·누락을 확인한다. 동영상과 프레임 적용 여부도 확인 대상이다.
2. **퀘스트:** 사이트별 방문 구분, 먹이 횟수와 포획·진화 반영, 완료·보상 수령·중복 수령 방지, 적용되는 초기화 규칙을 확인한다.
3. **먹이:** 30분 배고픔, 배고플 때만 먹이 제공, 경험치 +2, 행복 3회, 3회 먹이 트리거 및 저장·재접속 동작을 확인한다.
4. **성장:** 경험치 누적과 최대 레벨 5, 레벨 3·5 진화, 돌 부족·소비 처리, 레벨 3·4 행동 해금 및 진화 후 표시를 확인한다.

등장 시 펑 터지는 연출, 화면 이펙트 확장·뽑기, 회의록·포스터·돈 신청 등은 현재 네 가지 점검과 별도 후속 항목이다. 사용자 요청 없이 함께 구현하지 않는다.

## 작업 트리 주의사항과 검증 상태

문서 작성 전부터 아래 파일에 미커밋 변경이 있었다. 이 세션이 만든 기능 변경이 아니며, 후속 작업에서 보존하고 실제 diff를 먼저 확인한다.

- `backend/src/main/java/webket_monster/backend/quest/dto/SyncActivityRequestDto.java`
- `backend/src/main/java/webket_monster/backend/quest/service/QuestService.java`
- `frontend/content.tsx`
- `frontend/popup.tsx`
- `frontend/services/monsterService.ts`
- `frontend/services/questService.ts`

현재 검증 상태: 일부 코드 읽기만 완료. 빌드, 자동 테스트, API 호출, 브라우저 확장 프로그램 실행, 프레임 시각 검증은 미실시. 프런트엔드의 `npm test`는 실제 테스트가 아닌 실패용 기본 스크립트로 되어 있다.
